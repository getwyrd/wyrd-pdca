feat(metadata-tikv): complete-or-fail-loud prefix scan (M4.3, #254)

The TiKV metadata backend's prefix listing pulled a whole prefix over the
network in a single unbounded read. For a prefix larger than one network
page that read had no completeness guarantee and no documented snapshot
semantics, so a listing could come back silently incomplete. Garbage
collection builds its never-reclaim safety set from a full `inode:`
listing, so a truncated listing is silent data loss, not just slowness.

Replace the single-shot read with an internally paged scan that holds one
transaction — a single read timestamp — across every page, so the whole
result is one consistent snapshot. The scan now returns the complete
matching set or fails loud with a descriptive error when an interim
per-listing cap is exceeded; it never returns a truncated result. The
per-listing cap is a correctness bound, not a tuning knob, and the caller
that owns telemetry surfaces the operator-visible signal.

A module-level contract now documents the read-consistency guarantee:
a fresh snapshot per get and per scan, one consistent cut across all
pages of a scan, and why rename's read-then-commit stays safe through the
commit-time precondition re-check under the locking rule rather than read
freshness. The metadata trait is unchanged.

Fixes #254
