  - **#261 (read-snapshot semantics):** a **fresh-TSO snapshot per `get`/`scan`**, and **one snapshot held across all internal pages of a single `scan()` call** (a consistent cut — required *because* this slice pages internally). Stale/follower/cached-ts reads are **rejected for M4**, documented as the future relaxation behind the `meta:version` fence (ADR-0015 Option C; read-your-writes / clause 3 becomes cross-zone behaviour only later). The module-level read-consistency **contract doc lands with this slice**. https://github.com/getwyrd/wyrd/issues/261#issuecomment-4871148134
  - **#262 (interim paging cap — a correctness constraint, not a tuning knob):** GC builds its never-reclaim safety set from a **full `inode:` scan**, so a silently truncated scan is **data loss**, not slowness. The interim cap this slice implements **MUST fail loud on breach** — return `Err` + an operator-visible audit signal (ADR-0011) — and **MUST NEVER return a partial `Vec`**. https://github.com/getwyrd/wyrd/issues/262#issuecomment-4871176010
- **Defect / goal:** M4.1's skeleton `scan` (`crates/metadata-tikv/src/lib.rs:237-260` on the current integration branch — commit `a018b0e`; merged via #252/PR #421, unchanged by M4.2/#253 which touched only `commit`) already computes the bounded range `[prefix, prefix_upper)` but does **one unpaged** `txn.scan(range, u32::MAX)` — a single unbounded range read that pulls a whole prefix over the network into the gateway heap in one shot, with **no internal paging**, **no completeness guard**, and **undocumented read-snapshot semantics**. M4.3 replaces that shortcut with an **internally-paged** range scan that (a) holds **one consistent snapshot across all pages**, (b) materializes the full owned `Vec<(Vec<u8>, Bytes)>` (order stays unspecified), (c) **fails loud** rather than truncate when an interim cap is breached, and (d) **documents** the `get`/`scan` read-consistency contract per #261.
- **Success criterion:** a prefix that spans **more than one internal page** returns the **complete** set of matching `(key, value)` pairs — never a silently truncated subset — observed as a single consistent cut; when the interim cap is exceeded the call returns **`Err`** (with an operator-visible ADR-0011 audit signal), **never a partial `Vec`**; the shared `MetadataStore` conformance suite (#252) still passes for both backends and no consumer's order-independence regresses; and the module carries a read-consistency contract doc stating the fresh-TSO-snapshot-per-call / consistent-cut-across-pages semantics and why `rename`'s read-then-commit is safe (the commit precondition re-check under the locking rule, not read freshness). `cargo xtask ci` stays green on a machine with **no** TiKV (the tikv module + the endpoint-gated at-scale test skip cleanly); the behavioural at-scale proof runs under `cargo xtask tikv-conformance` against the throwaway `deploy/` single-node TiKV. **BINDING:** completeness-or-fail-loud + one-consistent-snapshot-per-`scan` + the documented contract. **ILLUSTRATIVE:** the exact paging mechanism, page size, and cap value are Do's call within the invariant.
- **Invariant to restore:** a `scan(prefix)` **either returns the COMPLETE set of keys with that prefix, or fails loud (`Err` + audit signal) — it must NEVER return a silently truncated subset**, and it observes **one consistent snapshot (a single TSO timestamp) across all internal pages** of the one call. Sourced: the completeness-or-fail-loud half from #262 + ADR-0011 (Durability telemetry / operator-visible audit) — a truncated `inode:` scan corrupts GC's never-reclaim safety set (data loss); the consistent-cut half from #261 + ADR-0015 (Consistency contract — TiKV snapshot isolation at a PD timestamp). Stated over the scan CATEGORY (any prefix, any size), not the repro fixture. (Plan-exit note: this is a feature slice with a data-safety invariant, not a structural/lifecycle defect, so the category-gated no-mechanism plan-exit gate doesn't bind; the invariant is nonetheless widened past any single guard — it governs every `scan` caller, not one module.)

## Verified backend facts (tikv-client 0.4.0 — so Do doesn't re-derive them)

- **Bounded range already exists:** `keyspace::prefix_upper_bound(prefix)` (`crates/metadata-tikv/src/lib.rs:52`, within the pure `keyspace` module `lib.rs:27-107`, unit-tested) yields the exclusive upper bound; `scan` (`lib.rs:237-260`) already builds `[start, upper)` (or `[start, ..)` for empty/all-`0xff`). The M4.3 change is **paging + one-snapshot + fail-loud cap + doc**, not re-deriving the range.
- **One snapshot across pages (safe default = keep `begin_pessimistic`):** the current `scan` opens **one** `begin_pessimistic` txn and does a single `txn.scan`; a pessimistic txn already reads at one start timestamp, so **holding that ONE txn across all internal pages already yields the #261 consistent cut** — the SIMPLEST correct implementation does not switch read APIs. A switch to a lighter snapshot read is OPTIONAL and its exact tikv-client 0.4 shape is **UNVERIFIED at Plan** — do NOT assume `client.snapshot(ts, ..)` / `begin_optimistic` exist as written (only `begin_pessimistic` is used anywhere in the crate today; the pin is `tikv-client = "0.4"`; reconfirm any new API at build time, the #260 caveat). Whatever the read path, it MUST be a single fixed timestamp for the whole call and MUST preserve the existing `rollback_then` drop-safety discipline (an active txn dropped under `CheckLevel::Panic` aborts the process — see M4.1/#253 build-notes).
- **Scan callers are verified order-independent (backs the "no order-dependence" invariant):** every `MetadataStore::scan` consumer is a `for (k,v) in scan(..)` accumulation into a set/map — `core/src/repair.rs:93`, `core/src/write.rs:352`, `custodian/src/backfill.rs:79,159`, `custodian/src/desired_state.rs:133`, `custodian/src/gc.rs:222,264,279`, `custodian/src/rebalance.rs:147`, `custodian/src/reconstruction.rs:468` (matches proposal 0015 §"Composition, not refactor"'s consumer audit). **`gc.rs:222` is the `scan(b"inode:")`** that builds GC's never-reclaim safety set — the concrete caller #262's fail-loud requirement protects; a silent truncation there is data loss.
- **Locking rule is unchanged and load-bearing:** `commit` (`lib.rs:262`) already reads every precondition key with `get_for_update` under `begin_pessimistic`, which is what makes `rename`'s read-then-commit safe (ADR-0015; proposal 0015 §"mandatory rule"). This slice **documents** that safety; it does **not** alter `commit`.
- **Never the raw API:** do not use `RawClient::compare_and_swap` or the raw scan — single-key/raw APIs cannot mix with the transactional API on the same database (proposal 0015 mandatory rule).

## Invariants to hold (from the design corpus)

- **Unchanged trait:** `crates/traits/src/lib.rs:338-344` (`MetadataStore::get`/`scan`) is byte-for-byte untouched — no paginated/streaming method, no signature change (M4's premise).
- **Completeness-or-fail-loud:** `scan` returns the full matching set or `Err` + an ADR-0011 audit signal; **never** a truncated `Vec` (a truncated `inode:` scan is GC data loss — #262).
- **Consistent cut:** one fixed read timestamp across all internal pages of a single `scan()` (#261; ADR-0015 SI).
- **Order stays unspecified:** callers must not (and per the audit do not) rely on scan order; the materialized `Vec` order is not a contract.
- **Gate honesty:** `cargo xtask ci` remains the single gate and must pass without a live TiKV; the at-scale scan test is additive (endpoint-gated), reached via `cargo xtask tikv-conformance` against the `deploy/` throwaway.

## Known NEEDS-HUMAN (expect the reviewer to flag; not blockers to building)

- **Endpoint-gated red→green:** the per-fix `C4-verify` gate cannot observe the at-scale scan red→green (no TiKV in the verify worktree; the test skips) — the proof is the `cargo xtask tikv-conformance` run against `deploy/`, recorded in build-notes. The whole-tree `C4-ci` still gates; the pure paging/cap decision unit tests give a Check-observable red→green.
- **Read-consistency doc = a documented decision:** the module-level contract doc records an architecture decision (#261, ADR-0015 Option C). A reviewer may flag doc-of-a-decision as human-confirmable (INTEGRATION §4 human-only items) — it restates an already-accepted decision, mints no new ADR.
- **The ADR-0011 "operator-visible audit signal" needs its concrete form settled.** `metadata-tikv` has **no telemetry/tracing path today** (deps are traits/tikv-client/tokio/async-trait/bytes only). The fail-loud cap-breach must return `Err`, but *how* the operator-visible signal is emitted is a design call: (a) the store returns a **descriptive `Err`** and the GC/custodian caller (which already has telemetry) surfaces the ADR-0011 signal — the lighter, dependency-free option; or (b) the store gains a light `tracing`-style emit itself (a new dep → ADR-0003/ADR-0016 review). Do should prefer (a) and record the choice; the reviewer/human confirms it satisfies #262.
- **The interim cap VALUE may be human-facing, not pure implementation.** A "max dirents per listing" bounds user-visible directory size; #262 calls it "a correctness constraint, not a tuning knob." Do picks a value, but if it reads as a product-facing limit the human confirms it (and it belongs in the documented contract, not just a constant).
- **Sequencing vs #419 (validated — the design wants #419 first).** #419's body explicitly frames itself as landing "**before M4.3**," and its `scan-is-consistent-cut` property "pins #254's one-snapshot-across-internal-pages requirement"; #254 is the slice that "runs these against TiKV's native scan." So `Depends on: 419` is set. It is a **verification-level** dependency (not a compile blocker) and #419 is **necessary but not sufficient** (fixture-scale semantics only; #254 still owns paging-at-scale + fail-loud-cap tests). **The human's call:** run/brief #419 first (recommended by the design), or drop the `Depends on` and ship #254 ahead — accepting that its core one-snapshot invariant has no shared executable pin at Check, resting on #254's endpoint-gated `tests/scan.rs` until #419 lands.
- **Check-observability is contingent on Do factoring pure logic.** The named `tests/scan.rs` is endpoint-gated and SKIPS at Check, so the *only* flippable red→green here is the paging/cap **decision** unit test — and only if Do extracts that logic pure. If Do cannot, this slice rests entirely on the deferred `cargo xtask tikv-conformance` proof (a pre-declared C2/C4 sign-off item, not a surprise).
