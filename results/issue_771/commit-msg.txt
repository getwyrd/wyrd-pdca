Add decoder for multipart retirement obligation records

The multipart commit protocol (proposal 0016) already writes two kinds
of key naming a "retirement obligation" - bytes to orphan-mark and
records to delete once an upload attempt is superseded, aborted, or a
generation is replaced. Nothing in the codebase could read the value
those keys point at: the grammar for the key existed, but the record
it names did not.

This adds that record. `decode_retire_obligation(key, bytes)` takes
both the key and the raw bytes together, because an obligation's
identity depends on the key that names it (its mode - orphan-mark
bytes vs. delete records - and its token's scope), and a decode that
can't see the key can't check the value against it. Every shape that
none of proposal 0016's writers can produce is rejected with its own
typed error rather than silently accepted; every accepted value
re-encodes back to the exact bytes it was decoded from.

One record-shape question took several rounds to settle: whether a
retired object generation can name both an inline chunk list and a
separate segment group, or must name exactly one. It mirrors the
generation it retires, which is always one shape or the other (never
both), so the decoder now makes "both present" a decode error instead
of a value the program has to keep asking "what if both?" about.

This lands the record shapes and the decoder ahead of any code that
writes or drains them - the same order the two records beneath it
(the admission ledger, the session/part records) landed in. No
production code path calls this yet; the writers that will are a
separate, later change.

Fixes #771
