feat(metadata): add bounded cursor-keyed scan_page primitive

MetadataStore's only enumeration primitive, scan(prefix), returns
whole-or-Err against a fixed cap (SCAN_CAP = 1 << 20,
crates/traits/src/lib.rs:286). Two multipart-era populations exceed
that cap and are therefore un-walkable today: the retire: namespace
is deliberately unbounded, and GC's orphan: ledger can install ~1.78M
marks against the 1,048,576 cap after one maximum segmented-object
retirement (crates/custodian/src/gc.rs:322). When that happens the
scan fails whole and aborts the entire reconcile pass before scrub,
reconstruction and rebalance run
(crates/custodian/src/reconciliation.rs:78-85).

Add scan_page(prefix, after, limit) as a required MetadataStore
method: a bounded, cursor-keyed page over byte-lexicographic key
order, with an exclusive cursor (a page starts strictly after
`after`), a completeness guarantee for any key present throughout the
walk, and a page bound of min(limit, effective cap) that can never be
breached. limit == 0 is rejected with a named error rather than
returning an empty page that falsely reports progress.

Every fill loop (redb, FoundationDB, TiKV) now shares one fullness
predicate, page_is_full (crates/traits/src/lib.rs:545), instead of
re-deriving "the page is complete" independently per backend. That
removes a class of silent-truncation bugs where a backend's own loop
disagreed with the cursor it handed back: a short page from a chunked
substrate read (FDB) or a client-side region merge (TiKV) was
previously indistinguishable from a genuinely exhausted prefix, so a
caller walking retire: or orphan: could stop early and silently skip
an obligation it must retain forever.

The four normative clauses (order, exclusive cursor, termination,
no-skip-of-stable-keys) are added to the shared metadata-conformance
suite and run against redb, both DST simulator stores, and (off the
default gate) live FoundationDB and TiKV clusters, so every backend
is held to the same oracle. No caller adopts scan_page in this
change; the retire: drain and orphan: ledger walk are separate,
follow-on changes.

Fixes #634
