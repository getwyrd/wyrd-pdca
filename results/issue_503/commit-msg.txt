s3 gateway: store and serve object ETag, Content-Type, Last-Modified

Many S3 SDKs validate the ETag on upload and rely on the stored
Content-Type on download; the gateway returned neither — PutObject
answered an empty 200 and GetObject always served
application/octet-stream. That breaks client-side integrity checks and
content typing, and blocks HeadObject (#506), server-side copy (#504),
and multipart, which all need a settled object-metadata model to build
on. ADR-0047 (docs/design/adr/0047-object-metadata-model.md, shipped
here) records that model; this change implements it:

- InodeRecord gains three flat optional fields — etag, content_type,
  modified — committed atomically with the chunk map. Each is Option +
  #[serde(default)], so records written before this change still decode
  and degrade on the wire to the old behaviour (no ETag header,
  application/octet-stream) rather than to an error.
- Metadata is stamped only at content publication (create and the
  superseding overwrite commits). Reconstruction, backfill, and
  rebalance re-commit the SAME content, so they preserve the stored
  trio: a repair never moves Last-Modified or drops the content type.
  An overwrite is a fresh publication and re-stamps all three.
- The ETag is the quoted lowercase-hex SHA-256 of the content — the
  digest the write path already streams, so no second read — treated as
  an opaque change token, not MD5 (S3 documents ETag as not guaranteed
  to be MD5; an MD5 dependency would buy compatibility only with
  clients that violate that opacity — see ADR-0047).
- The gateway seam stays transport-neutral: put_object_streaming takes
  the declared content type and returns the committed ETag; ObjectRead
  carries the trio alongside size. Everything remains streaming.
- Last-Modified is rendered as an RFC-7231 IMF-fixdate by a small
  in-tree formatter, avoiding a new date dependency.
- The GET arm degrades a malformed *stored* content type or etag
  (reachable via store corruption or out-of-band edits) to the default
  type / an omitted header instead of panicking the response builder,
  so one bad stored byte can never deny every read of an object.

Fixes #503
