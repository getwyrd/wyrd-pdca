The advisory conclusion is that another implementation pass is warranted: the supplied regression matrix passes, but an independently exercised reader-grace failure remains, destination choice rejects feasible work, and the suite misses a safety-critical write-refusal mutation. Source citations below are relative to `$PDCA_TARGET`; evidence files are relative to this review directory. The target is readable and contains the declared retirement drain and redb dependency. Reverse-applying `patch.diff` passes `git apply --reverse --check`; the original patch is restored and no source fixes were made.

1. **F1 — Preserve reader grace when an in-place repair loses its adoption (P1; C5).** Pre-marking also marks a position the old placement already names (`crates/custodian/src/premark.rs:207`). If the rebuilt write succeeds but an unrelated root-generation update makes adoption lose, `repair_chunk` returns `Conflict` with that mark still present (`crates/custodian/src/reconstruction.rs:1279`). The next pass sees healthy bytes and drains the repair obligation (`crates/custodian/src/reconstruction.rs:916`, `crates/custodian/src/reconstruction.rs:494`), without consuming the live position's mark. Once that stamp ages, a production multipart Complete can supersede the object and a GC-only pass immediately deletes the fragment, before retirement establishes fresh grace (`crates/custodian/src/gc.rs:685`). A reader of the just-superseded placement therefore loses its grace protection. The independent probe started with no stale mark, forced rebuilding on server 5, raced a version bump, ran the healthy follow-up pass, advanced 60,001 ms, then ran Complete and GC. The preservation assertion failed for **both flat and segmented objects** (`review-probes.log:82`, `review-probes.log:86`). Account for already-referenced destinations across failed adoption/crash and add that regression. This is distinct from [#825](https://github.com/getwyrd/wyrd/issues/825)'s deferred empty-mark cleanup and unknown late-write cases: this write definitely succeeded on an already-live position and GC reclaims it too early.

2. **F2 — Keep exclusions specific to the fragment position (P2; C5/T3).** `choose` reads a mark keyed by server **and fragment**, then adds only the server to `ruled_out` (`crates/custodian/src/premark.rs:157`, `crates/custodian/src/premark.rs:162`). In two available domains, marks blocking `(server 2, index 0)` and `(server 3, index 1)` make it exclude both servers and return `None`. The assignment `index 0 → server 3`, `index 1 → server 2` is valid and has no blocked marks. The independent probe checks those two positions are usable and then fails because `choose` rejects the assignment (`review-probes.log:77`). Both movers use this selector. Retry assignments at position granularity, preserving distinct-domain constraints, and cover a multi-fragment swap; unreadable marks must not force an unnecessary indefinite stall when an alternative exists.

3. **F3 — Make write refusal and each deadline independently load-bearing (P2; T5).** The independent mutation run replaces the entire `premark::refusal` body with `Ok(None)` and **all custodian tests still pass** (`review-mutants-capped.log:3`; also frozen `gate-logs/C5-mutants.log:15`). That mutant would adopt an unwritten destination when a deadline-refused write leaves an otherwise unchanged pre-mark. Current D7b legs first advance beyond full grace and let GC delete the mark; consequently the adoption CAS fails even if the mover ignores the write error (`crates/custodian/tests/move_destination_marks.rs:1277`, `crates/custodian/tests/move_destination_marks.rs:1335`, `crates/custodian/src/rebalance.rs:2176`). Add refusal while the pre-mark still stands and no destination bytes exist, and assert no adoption, retained obligation/drain work, and the refusal audit event. Also test the `W_repoint` and `stamp + W_write` boundaries separately, inside grace; the frozen `<`→`<=` survivor confirms the boundary is unpinned (`gate-logs/C5-mutants.log:14`). These are test gaps; the current refusal implementation itself handles errors.

4. **F4 — Keep existing DST evidence faithful to the new protocol (P2; T5).** The changed losing-race assertion only requires one structured mark whose key differs from the vacated key (`crates/dst/tests/custodian.rs:6267`), despite knowing the destination is server 3 (`crates/dst/tests/custodian.rs:6153`). It can pass with the actual copied position unmarked; assert its exact key and evidence. Its `Rewrite` rival also publishes the destination without consuming a pre-mark (`crates/dst/tests/custodian.rs:6189`), allowing a state the new move protocol forbids. In addition, existing committed-repair fixtures still set a zero write window (`crates/dst/tests/custodian.rs:664`) and their `MemDServer` ignores deadlines (`crates/dst/tests/custodian.rs:298`). These fixtures now approve writes a conforming server would reject immediately. Update the existing fixture's clock/window and deadline behavior and make the rival obey adoption semantics. This does not request the new interleaving campaigns already deferred to #682.

The frozen batch's duplicate reports about server exclusion, in-place grace, and the DST orphan assertion are consolidated above. The same-millisecond event-identity concern at `crates/custodian/src/premark.rs:301` is not promoted to an additional safety defect: this code always re-stamps, never takes a same-identity skip, and equal timestamps share the same grace/deadline; the cited staged peer uses the same construction (`crates/custodian/src/reconstruction/staged.rs:805`). The log’s identity-collision claim alone does not establish a separate unsafe adoption schedule in this implementation. No new capability probe or load-time symptom guard was added: the mark/deadline checks implement the requested lifecycle contract. The #825 and #682 deferrals remain settled; no DCO finding is inferred from the synthetic local commit.
