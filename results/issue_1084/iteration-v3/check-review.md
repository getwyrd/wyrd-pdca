1. **FAIL — a reused move identity lets adoption publish a placement over missing bytes.** `move_event` uses only chunk ID and millisecond timestamp, so two moves begun in the same tick produce identical pre-mark values (`crates/custodian/src/premark.rs:402`, `crates/custodian/src/premark.rs:516`). In the independent probe, move B pauses before its absent-key pre-mark commit; move A pre-marks, writes, and pauses before adoption. GC then ages and deletes A’s destination and mark. B resumes: the key is absent again and the unchanged root/segment pins still hold, so B restores the identical mark bytes, then correctly refuses its own stale write. A’s adoption nevertheless satisfies the exact-value condition at `crates/custodian/src/premark.rs:479`. Both flat and segmented runs return `Changed`, publish placement `[3, 4, 2]`, and leave fragment 2 absent on server 2 (`review-probes.log:42`, `review-probes.log:47`). Use a fresh identity per move that cannot recreate another move’s evidence after GC; add this delayed-pre-mark/adoption regression. This is the per-move nonce requirement at `docs/design/proposals/draft/0016-multipart-commit-protocol.md:1179`, with an observed safety consequence, not merely a naming convention.

2. **FAIL — a legal in-place write can land after its only reclamation evidence is gone.** The in-place path creates no pre-mark (`crates/custodian/src/premark.rs:417`) and relies on later unreferences having later stamps. A competing move samples its vacated mark’s timestamp before committing (`crates/custodian/src/premark.rs:470`), so that ordering is not guaranteed. The probe holds A’s adoption batch, stamped at T0, after A copied server 5’s fragment to server 2. At T0 + grace + 1, B starts an in-place repair on server 5 and pauses its write after authorization. A then adopts and installs its old T0 vacated mark. GC sweeps that aged, fragment-less mark; B’s still-valid deadline then permits its write. Both shapes end with placement `[3, 4, 2]`, bytes on server 5, and no mark there (`review-probes.log:32`, `review-probes.log:37`). The in-place write’s evidence must survive an already-prepared, delayed vacate. This is distinct from #825’s deferred unknown-write/pre-mark settling cases: the write lands successfully within its deadline.

3. **FAIL — the new refusal paths falsely certify restored redundancy.** Destination admission returns `Assessment::Blocked` when every usable position is reclaiming or unreadable (`crates/custodian/src/reconstruction.rs:900`), but that state only increments a metric (`crates/custodian/src/reconstruction.rs:368`). A deadline refusal becomes `RepairOutcome::Aborted` (`crates/custodian/src/reconstruction.rs:1284`), which also only emits telemetry (`crates/custodian/src/reconstruction.rs:469`). Neither contributes to the final non-certification decision at `crates/custodian/src/reconstruction.rs:516`. Independent reclaiming-destination and exact-deadline probes each return `Satisfied`, with `owed=true` and no destination fragment, on both shapes (`review-probes.log:3`, `review-probes.log:18`). Propagate these new refusals into a non-satisfied outcome while retaining the obligation. `Satisfied` explicitly means reality matched the desired state (`crates/custodian/src/reconciliation.rs:23`); the continuous server loop may keep polling, but that does not make this public certification correct.
