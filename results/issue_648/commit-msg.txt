core: add the segmented chunk-map record shape and codec

InodeRecord.chunk_map has been a bare inline Vec<ChunkRef>
(crates/core/src/metadata.rs:268 on origin/main), so an object's whole
chunk list has to fit in one metadata value — 100 KB on the tightest
backend — well below the >10 GiB target object size. This adds the
ChunkMap::{Flat, Segmented} shape, the segment/segment-group record
types, their decode-time structural invariants, and the seg:/seggrp:
key helpers, so a large object's chunk list can eventually live across
multiple records instead of one.

The two shapes are discriminated by JSON type on the wire, so every
pre-existing flat record still decodes and re-encodes byte-identically
and every existing CAS commit keeps matching the bytes already in the
store. A malformed segmented record is rejected at decode rather than
producing a value a caller could half-resolve, and every existing
chunk_map read site now treats a segmented map as a typed error
instead of silently reading it as an empty chunk list.

This slice lands only the record shape and codec: nothing yet writes
a segmented map (no producer, no resolver), so on-disk and runtime
behavior is unchanged until the follow-on slices land.

Fixes #648
