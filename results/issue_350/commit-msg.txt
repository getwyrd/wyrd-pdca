Backfill identity placement on pre-M3 committed chunks

Clusters that predate M3 hold committed chunk records whose placement
vector was never written out — it is empty and only resolved implicitly,
each fragment falling back to its identity D-server on read. That
fallback exists solely for these mixed-era records, but there is no way
to tell how many remain or to drain them, so a migration-only
compatibility path stays load-bearing with no path to retirement.

This adds a custodian backfill pass that scans committed inode records
and, for every chunk whose placement is empty, materializes the explicit
full-length identity vector (placement[i] == i) directly onto the
record. Each rewrite commits version-conditionally on the exact prior
record — the same compare-and-set the writers and other custodians
already race through — so a concurrent writer or custodian wins the race
and the fill is simply retried on a later pass rather than clobbering the
winner. A malformed (non-empty, wrong-length) vector is left exactly as
committed and surfaced as an operator signal; it is never rewritten. The
pass emits the count of empty-placement committed records still remaining
on the durability-plane telemetry every pass, so an operator can watch
the pre-M3 population drain to zero.

The read and write paths are unchanged: this makes an already-implied
placement durable, it moves no fragment. Removing the fallback branch
itself, once the drain metric reads zero in production, is deliberately
left to follow-up #363.
