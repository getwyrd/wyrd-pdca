validate: add the capability matrix and its run verdict

wyrd-validate has no way to say which S3 operations a Wyrd release must
support, which it must refuse, or how a refusal must look. Without that, a
validation run cannot tell a correct refusal from a wrong answer, and an
operation that starts half-working goes unnoticed.

Add a pure matrix module that declares those expectations for today's
gateway, picks them by the version the server reports, judges each observed
answer and folds the results into PASS, FAIL or INCONCLUSIVE. An unknown
version is never read as release 0.0.0. A cut-off body or a lost answer can
leave a result unproved, but never hides a wrong status or byte that already
arrived.

The checks for operations that must succeed come in #1006, so those rows are
reported unproved and never passed. Nothing in the binary calls the module
yet. Proposal 0017 is amended to match: a 5xx is an answer and is fatal, and
the pre-0.1 profile is edited in place until the first 0.1.0 release.

Fixes #1005
