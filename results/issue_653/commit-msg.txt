core: add staged publication committer for segmented chunk maps

An object's chunk map must fit in one metadata value, which caps it at
MAX_MAP_CHUNKS (158) chunks, about 158 MiB at the default 1 MiB chunk
size. Larger objects need a segmented map, and the record shapes and the
read side for one already exist, but nothing could write one. A segmented
map is also too big for one transaction, so it has to be published in
stages without ever leaving a live object that names a segment that is
missing.

Add wyrd_core::staged_publication::publish. A map of at most
MAX_MAP_CHUNKS chunks is published flat, as one batch. A larger map is
split into seg: records sized by encoded bytes, written in batches bounded
by both bytes and operation count, read back in full and checked
byte-for-byte, and only then made live by one batch that flips the inode
root together with the caller's own state change.

The committer knows nothing about multipart sessions. The caller supplies
a fence record and, per batch, a contribution that pins and advances it.
Before anything is written the committer refuses a plan that does not
fit, a batch over budget, a contribution that does not pin the fence, a
flip that does not move it, a fence that returns to a value it already
left, and a contribution that touches the inode, dirent or segment range
the committer owns. A caller's resume cursor only says where to start
writing; the check before the flip always covers every segment.
planned_segments exposes the segment count the caller's flip must expect,
which can exceed ceil(chunks / MAX_SEG_CHUNKS) for wide chunk references.

The module documents the two duties left to the caller: a rollback must
commit a move of the fence before it deletes any seg: record, and a
contribution must not touch committer-owned keys (the second is also
enforced). The crosscutting-concepts chapter gains a paragraph on staged
publication.

There is no production caller yet; the multipart Complete (#658) will be
the only one, so no existing behaviour changes. New tests:
crates/core/tests/segmented_publication.rs (round trip, batch bounds,
refusals with zero commits, resume, flip atomicity, rollback in both
orders) and the madsim scenario crates/dst/tests/segmented_publication.rs
(commit-ambiguity faults, recovery at the same epoch, a rival rollback).
