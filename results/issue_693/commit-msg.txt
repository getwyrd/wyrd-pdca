core(multipart): answer table + ETag/fingerprint digests for #654 3/3

Add the typed vocabulary and pure functions a multipart upload's verbs
(UploadPart, CompleteMultipartUpload, AbortMultipartUpload, ListParts,
ListMultipartUploads) answer with, in every session state and when no
session record exists at all. Every one of the 25 verb x state cells
now has a typed answer instead of a generic error or an HTTP status;
no answer enum is `#[non_exhaustive]`, so a new verb or state must be
handled everywhere at compile time, and a new outcome variant cannot
silently fall through to a wrong status at any protocol gateway.

Two digests give a completed upload its identity: `multipart_etag`
composes the object's ETag from the named parts' raw digests (never
MD5, per ADR-0047), and `complete_fingerprint` lets a retried Complete
be told apart from a different assembly under the same upload id. Both
refuse an empty, out-of-order, or duplicate part list rather than
silently sorting it, so a client's own ordering is never rewritten
underneath it. `sha2` (already a workspace dependency) is added to
crates/core to compute them.

The persisted `Completion.etag` field now stores the composed ETag
whole (hex digest plus part count) instead of a bare digest, because
by the time a retry reaches the tombstone the individual part records
it was computed from may already be gone. The architecture doc is
updated in this same commit to describe the stored form, since the
project's contributor rules treat a persisted-record change as
requiring the living doc to move with it.

record types this table and these digests operate over.
