metadata: add the FoundationDB backend (ADR-0042), off by default

ADR-0042 chose FoundationDB as Wyrd's production distributed metadata store,
superseding ADR-0008, but nothing implemented that choice. An operator who
wanted metadata on a real distributed cluster had only the embedded
single-node option, and everything downstream of the store — the CI harness,
server-side backend selection, client packaging, the #257 go/no-go battery —
was blocked on code that did not exist.

This adds `crates/metadata-fdb`, an `FdbMetadataStore` over the *unchanged*
`MetadataStore` trait. It is composition, not a refactor (ADR-0010): no trait
changes, and the shared conformance suite is untouched, so redb and TiKV keep
passing the same seven contracts FoundationDB now passes against a live
`fdbserver`.

The backend sits behind an `fdb` Cargo feature that is off by default,
mirroring `wyrd-metadata-tikv`. A default build links no `libfdb_c` and
behaves exactly as before; nothing in the server constructs this store yet —
that selection arm is a later issue. The dedicated `cargo xtask
fdb-conformance` job brings up a throwaway single-node cluster, runs the
shared suite plus the driver's contention and scan legs against it, and always
tears it down.

Three rules the trait states but the shared suite cannot exercise are pinned
by tests here. FDB error 1020 becomes `Ok(Conflict)` only for a batch that
carried preconditions, so a blind write is never silently swallowed by a
caller that uses `?` and ignores the outcome. Error 1021 is never retried and
never a conflict, because a `WriteBatch` is not guaranteed idempotent and the
commit may already have landed. And a scan past the 2^20-key cap fails loud
with `ScanCapExceeded` rather than returning a truncated result set, which
would be data loss (#262, ADR-0011).

`foundationdb` 0.10 is a new dependency, pinned with `default-features =
false` and the `fdb-7_3` API feature so client and server versions agree. Its
build-time graph reaches `libloading` under ISC, which is added to
`deny.toml`'s allowlist with an ADR-0003 §2 rationale; no ISC-licensed code is
linked into a shipped Wyrd binary.

This targets `main` directly rather than an integration branch: the M4 branch
merged as 182ae4f97ab8a3e10f0438597c67559a3e11a393, satisfying the issue's
"after feat/m4-production-metadata-backend merges" condition.

Fixes #438
