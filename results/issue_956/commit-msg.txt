validate: S3 client sends bulk deletes and unsupported-op probes

The validator's S3 client could not send a bulk DeleteObjects, or one request
for each operation an endpoint may not support (CopyObject, the six multipart
operations, GetBucketLocation and the bucket operations). It also let the AWS
SDK's endpoint rules reroute or refuse some bucket names before anything was
sent: S3 Express names, Outposts-alias names and names starting "arn:". A
DeleteBucket probe must name a bucket S3 forbids, so that it can never delete
one the caller does not own, and that only works if the name reaches the
endpoint exactly as given.

Add DeleteObjects and one probe per operation. Each reports the status, the S3
error code and the headers as sent, and keeps a 2xx beside any failure of the
body that follows it. A delete result is read row by row: deleted keys, error
rows with their key, code and message, the requested keys no row names, and
the rows that name no requested key. The client reports these and does not
judge them. A delete result that is cut short, malformed or over the 64 KiB
budget is refused beside its 200, never returned in part.

Replace the SDK's endpoint rules with the client's own path-style resolution:
every request goes to the configured endpoint with the bucket as one
percent-encoded path segment, signed for "s3" in the configured region. This
changes the existing verbs in two small ways, both documented: an endpoint
path is joined to the bucket with one "/", and the region is signed as given
(so "aws-global" is no longer signed as "us-east-1").

A request that cannot be built is reported as not sent, never as no response.
Timeouts keep their connect or operation phase.

Nothing calls the new verbs yet except their tests.

Fixes #956
