test: add live network-partition nemesis to Tier-1 Jepsen leg

Wyrd's Tier-1 Jepsen suite is meant to prove that a node which is cut off
from the network — but still running — cannot cause stale or torn data
when the network heals. Until now the leg that claimed to model a
"network partition" actually froze the whole node with `docker pause`.
A frozen node stops its own clock; a truly network-isolated node keeps
running, keeps its timers ticking, and only loses reachability. The suite
was therefore exercising a strictly weaker fault than the one it
advertised, and never tested a still-live, isolated node across a heal.

This adds a second, distinct isolation nemesis alongside the existing
freeze leg (which is kept as a cheaper check, not replaced). The new leg
isolates the node with a network-level packet drop that leaves the
container running and preserves its published-port mapping, then heals it
and asserts the same repair-path consistency properties plus a new one:
the isolated node stays live (its container reports `running`, never
`paused`) for the whole fault window — the property the freeze leg cannot
exhibit.

The isolation choice is a plain value with both alternatives representable
and a unit test that goes red if the network leg ever collapses back to a
freeze; a node-liveness check with negative controls guards the new
property. Both run at every CI build. The full containerized run stays
behind the existing privileged Tier-1 job, which now runs both legs.
