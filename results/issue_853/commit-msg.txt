validate: refuse non-conforming S3 responses and cap buffered bodies

wyrd-validate's verdicts are only as good as the facts its S3 client
reports. The client trusted the AWS SDK's reading of every response, and
the SDK reads leniently: an empty 404 became the error code NotFound,
which the server never sent; an HTML 500 or a cut-off <Error> document
became a clean S3 error; a GET body ended by a dropped connection became a
complete, shorter object; and PUT and DELETE trusted an error body whose
length disagreed with its Content-Length, where GET refused the same
bytes. Every error body, and every PUT or DELETE response, was also read
whole into memory with no limit: a 768 MiB chunked error body took the
process from 19 MiB to 794 MiB.

Now a response that is not a whole, well-formed, correctly framed S3
response is never reported as one, and the same bytes get the same
verdict on GET, PUT and DELETE:

- the client reads error bodies itself: an empty body is "no body", an
  <Error> without a <Code> is "no code in body", and anything but one
  whole <Error> document whose <Code> and <Message> hold only text is
  unreadable;
- framing that cannot mark where a body ends is refused, and so is
  anything the endpoint sends after the end the framing marks;
- error bodies are capped at a fixed 64 KiB budget as they arrive, and a
  PUT or DELETE success, which S3 sends without a body, may carry none;
- a successful GET still streams outside the budget. It is accepted with
  a correct Content-Length or with complete chunked framing, so chunked
  GETs, which the client used to refuse, now work.

To see what follows a response, the client drops the SDK's HTTP client
for a small connector of its own on hyper's HTTP/1.1 connection API, one
connection per request. That takes 13 crates out of the shipped graph and
adds none. Each GET and DELETE now opens a fresh TCP connection, as each
PUT already did.

The new test crates/validate/tests/s3_client_nonconforming_responses.rs
drives the production client against a loopback endpoint that writes
exact bytes. 20 of its 28 tests fail without this change and all pass
with it.
