- NEEDS-HUMAN — **Leg H can reject a correct detached Abort because its required state is transient.** `brief.md:344-349` requires observing the session as `Aborting` after releasing the held commit, but leg C explicitly requires the background drain and terminal delete (`brief.md:178-180`). Target `crates/core/src/multipart.rs:4637-4641` makes reclamation asynchronous after the fence; `docs/design/proposals/draft/0016-multipart-commit-protocol.md:550` shows `Aborting → drain → absent`. A conforming adapter can finish the settling read and delete an empty upload before the test next inspects the store; polling cannot recover that state. Revise the oracle to capture the applied fence/settling-read bytes in the wrapper, or hold terminal deletion until the assertion, while retaining the commit drop guard.

- NEEDS-HUMAN — **Removing the shared denylist entries also changes bulk DeleteObjects, outside the enumerated routing tests.** `brief.md:683-686` removes `uploads`, `uploadId`, and `partNumber` while keeping the guards unchanged; `brief.md:740-741` promises unchanged DELETE behavior. On the target, `foreign_subresource_on_delete` derives its refusals from that same list (`crates/gateway-s3/src/lib.rs:578-584`), and the bulk-delete interception runs before the normal bucket guard (`:1766-1787`). Consequently, with a valid DeleteObjects body, `POST /b?delete&uploads`, `?delete&uploadId=U`, and `?delete&part%4Eumber=1` lose their existing refusal and reach deletion. Revise the dispatch requirement to reject mixed operation selectors before this early return, and add signed requests asserting the chosen exact error and that the named objects survive.

- NEEDS-HUMAN — **The new Create route can bypass the existing object-key limit.** The brief explicitly relocates the bucket-slash check to multipart (`brief.md:139-153`) and assumes a key-length refusal exists (`:107-108`), but never requires or tests that refusal on Create. Target `crates/gateway-s3/src/lib.rs:489-501` requires the 1,024-byte decoded-key limit on creating paths; its implementation is inside ordinary `Method::PUT` (`:1895-1904`). Multipart Create is a POST, and core's `CreateRequest::object` accepts the caller's name (`crates/core/src/multipart/create.rs:46-60`); its preflight checks the much larger metadata-value ceiling (`:342-350`). Require Create to preserve `400 KeyTooLongError` before admission, with 1,024/1,025-byte decoded UTF-8 cases and unchanged session/admission state on refusal.

- NEEDS-HUMAN — **UploadPart routing omits the existing copy-request refusal.** `brief.md:115-171` enumerates routing safety cases, and `:421-427` scopes implementation to six verbs, but neither addresses `x-amz-copy-source` on `PUT /b/k?partNumber=1&uploadId=U`. Target `crates/gateway-s3/src/lib.rs:1853-1871` explains why streaming a copy request's body as ordinary upload data is destructive and refuses that header only inside the ordinary PUT arm. A new multipart dispatch before that arm can instead stage an empty or supplied body, replacing a part, while passing the listed tests. Require this unsupported copy form to retain `501 NotImplemented` before staging; test a live upload with an existing part and verify its ETag and bytes remain unchanged. This preserves a refusal without adding a seventh verb.
