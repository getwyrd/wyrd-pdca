feat(core,custodian,server): segmented chunk maps beyond one value

An object's chunk map is stored as one JSON metadata value, and every
backend caps a value at 100 KB (the tightest, FoundationDB's). At the
default chunk size that ceiling holds only ~165-381 MiB of object, well
short of the >10 GiB launch requirement, and every maintenance pass
(GC, scrub, restore, rebalance, reconstruction, backfill) plus both
read paths decode that same value, so any fix has to reach all of
them or risk stranding or deleting live data, not just widen the read
path.

InodeRecord.chunk_map now discriminates on JSON type: a flat array, as
today, byte-identical for every existing record, or a segmented object
that names a group and points at a bounded range of `seg:` records
holding the actual chunks. A segmented map is published by writing its
segments and then flipping the root in one CAS batch, so a crash
mid-publish never exposes a partial map, and the caller may attach its
own precondition and mutations to that same flip batch so a session's
state transition and the map's publication commit atomically or not
at all. One resolver, given the store and the record's root identity,
answers every consumer: it orders segments by their own index rather
than store scan order, re-verifies a resumed publication's already
written prefix instead of trusting it, and re-reads the root before
concluding a mid-read absent segment is corruption rather than a
concurrent retirement.

Every current chunk_map consumer is routed through that resolver:
GC's reference build (and therefore scrub), restore, rebalance,
reconstruction, backfill, both the gateway and core read paths, and
the chunk-id floor used before a gateway starts serving. Each has an
explicit containment behaviour for a single damaged object: the
gateway still starts, healthy objects still read and are not
reclaimed, and only the damaged object fails closed. Scrub, which
previously reported a clean bill for a store it could only partially
verify, now reports a distinct blocked outcome instead of silently
certifying an incomplete pass, and emits an operator-visible signal
before it does.

No production caller can yet publish a segmented map - that lands
with the multipart-upload session that supplies the fence and the
group nonce - so this ships the shape, the staged-publication
committer and the resolution contract ahead of that wiring.
