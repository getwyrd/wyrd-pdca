validate: S3 client reports HEAD, range GETs, listings as sent

The validator could only PUT, GET and DELETE one object, so it could not
check how an S3 endpoint answers a HEAD, a ranged or conditional GET, or a
listing. The SDK also reads these answers itself, so a listing cut short, a
body that stalls after a 200, or a 304 with no body could not be reported as
what the server sent.

Add those verbs, with both listing versions followed across pages. Each one
reports the status and every header line as sent, then reads the body itself
under the existing size budget and deadlines. A body that fails after a 2xx
head is reported beside that 2xx, and a listing is returned whole or not at
all. The verbs report only; they do not judge whether an answer is right.

Nothing calls the new verbs yet except their tests. The existing verbs behave
as before.

One limit remains: a head the HTTP library itself rejects, such as an invalid
Content-Length on a listing page, has no status to keep and is still reported
as no response.
