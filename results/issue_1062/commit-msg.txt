custodian: free the storage of aborted and replaced multipart uploads

When a multipart upload is aborted, when a Complete leaves some uploaded
parts unused, when a part is uploaded again, or when an object is replaced,
the old bytes are handed to the custodian as a retirement obligation. Until
now only the record half of that work drained: the bytes stayed protected
from garbage collection for ever, so the space was never given back.

The custodian's reconcile pass now drains these obligations in bounded
batches. For each fragment the obligation names it writes an orphan mark,
and only then deletes the record that named it; garbage collection reclaims
the fragment once the normal grace period has passed. Each mark is stamped
with the clock read for that step, after the obligation is read, so a
retirement installed earlier in the same pass still gets its full grace and
a reader that overlaps the replace is not cut off.

The drain never overwrites a mark garbage collection has already committed
to reclaim; it waits for that reclaim to finish and then marks the position
again. It stops with an audited hold, and changes nothing, where going on
could lose data or leave records behind: a placement it cannot trust, a mark
it cannot read, a session that still owns staged entries, or a reclaiming
mark over a record it must keep, which needs an operator. For a session it
deletes no part record until the segment records have drained, so a restore
check between two passes still reads the attempt as clean.

Garbage collection now also removes a drain mark that has no fragment once
its obligation is gone, so every mark the drain writes has a deleter.

This builds on the record drain in #1066.
