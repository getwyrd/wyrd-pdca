multipart: land Budget/AdmissionRecord decode validation

`crates/core/src/multipart.rs` names every multipart key (`mpu:`, `part:`,
`slot:`, `mpuctl`, ...) but stores no value type yet, so there is nothing to
stop a torn `mpuctl` admission-ledger record from being read back as a live
budget. Any store round trip that later reads `mpuctl` (#656-#659) would have
had to trust an unvalidated blob, and an internally inconsistent one lets a
gateway admit sessions past the memory bound the reconcile pass is sized for
-- an OOM landing on the maintenance plane rather than on the gateway that
caused it.

Add the two types this record needs: `Budget`, the five-field profile tuple
proposal 0016 names (`W_ref`, `MAX_PART_CHUNKS`, `MAX_PARTS_PER_SESSION`,
`MAX_INFLIGHT_PARTS`, `MAX_STAGED_CHUNKS`), with its `U_ref` and
`MAX_SESSIONS` derivations computed in exact (`u128`) arithmetic so a torn
field near its wire-type maximum cannot panic or silently wrap; and
`AdmissionRecord`, the `mpuctl` singleton `{ count, max_sessions, profile }`.
Both validate at decode: a `TryFrom` conversion behind `#[serde(try_from)]`
so a value that decodes cannot be malformed on any surface that reads it
(mirroring `InodeRecord`'s existing pattern), plus a typed
`decode_admission_record` peer of the existing `decode_segment_record` so a
caller can tell exactly which rule a stored ledger broke -- one distinct
`RecordError` variant per rule -- rather than parsing a message string.

Eight guards are enforced (structural relations only: a stored field may
not disagree with another stored field or with a format constant that
cannot move); three positive cases are pinned as things decode must NOT
reject (an over-limit occupancy count, or a profile value outside a range
this slice does not own) so the boundary between "malformed record" and
"configuration this deployment merely chose" stays where proposal 0016
(and the existing `MAX_ROOT_SEGMENTS` liberal-on-read precedent at
`metadata.rs`) draw it. No writer exists yet for this record -- that lands
with the store round trips in a later change -- so this is pure, decode-only
groundwork with no behavioural effect on any existing path.

Fixes #715
