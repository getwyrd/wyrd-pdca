core: store the segment-group nonce on every multipart session

A multipart upload's segment records live under a random nonce that is
independent of the upload id, so nothing on the session record could
recover it. Proposal 0016 needs that nonce for the session's whole life:
Create reserves it, each Completing attempt writes under it, the batch
that ends an attempt must name those records for deletion, and the
terminal delete must remove the reservation marker, including for an
upload aborted while still Open or Aborting. Without it on the record,
those segment records and the marker would have no deleter.

The session record (`mpu:<id>`) now carries `segment_nonce` in every
state: exactly 32 lowercase hex characters, right after `clock_source`
and before `epoch`. It decodes through `SegmentNonce::new`, so a missing,
malformed, repeated or misplaced nonce is refused, and a copy inside
`publish_target` is refused too. `publish_target` is unchanged; a
Completing attempt's group is the session's nonce at the attempt's fence
epoch. A rollback to Open keeps the nonce for the next attempt.

Two accessors expose it without re-parsing: `segment_nonce()` in every
state, and `attempt_segment_group()`, which is Some only for Completing.
`SegmentGroup::from_nonce` builds a group from an already-validated
nonce.

No production code writes session records yet, so there is nothing to
migrate. Every existing session fixture in the workspace gains the field,
and the architecture doc notes that 0016's `mpu:` row does not list it
yet.

Fixes #840
