core: publish a completed multipart upload as one flat object

Until now a CompleteMultipartUpload request could take the upload's fence,
but nothing turned the staged parts into an object: the parts stayed staged
and the key never appeared. This adds complete_upload, which takes the fence
and then publishes the named parts, in part order, as one object of at most
MAX_MAP_CHUNKS chunks through the staged-publication committer.

The publishing commit (the flip) does four things in one batch: it writes the
root, moves the session to Completed with the ETag and the request
fingerprint, installs retirement obligations for the published parts' records,
for any staged part the list left out, and for a superseded generation that
has chunks, and pins the bucket marker that validation read. So staged bytes
are always named by something, published chunks are never queued for
deletion, and nothing is published into a bucket that is gone.

When the flip loses to another write, the target and the bucket marker are
read again and the version is recomputed from the prior on each retry. A gone
bucket answers NoSuchBucket. Running out of retries answers OperationAborted.
A flip the store refuses for good stops with that error. In all three cases
the fence is released, so the session stays usable. An unknown flip outcome
returns the in-doubt error and sends nothing more. A list past one flat map
stops with a "segmented publication unsupported" cause until segmented
publication lands.

Nothing calls the new function in production yet; the S3 verb comes with
#670.
