Add the standing Elle consistency CI job and its DST regression loop

Data-safety verification was a one-shot achievement. The verdict dispatch in
crates/server/src/consistency_workload.rs routes the Elle verdict to a
privileged off-merge-gate job named "elle-register-verdict", but no such
workflow existed — the seat was empty. Nothing ran the checked consistency
run on a schedule, so a future regression that reintroduces a way to lose or
corrupt data would go unnoticed until the next manual run; and an anomaly,
had one surfaced, would have produced neither a tracked bug nor a permanent
deterministic regression.

This fills the seat and closes the loop end to end:

- .github/workflows/elle-register-verdict.yml (new): the standing privileged
  job. Daily at 07:00 UTC (the first free slot among the sibling nightlies)
  plus workflow_dispatch, nothing else; timeout-bounded; thin per the CI rule
  (ADR-0009 / ADR-0016: all decision logic stays in cargo xtask — the YAML
  provisions Docker, the FoundationDB client, a JVM, and the sha256-pinned
  elle-cli jar, then makes exactly one opt-in invocation, WYRD_TIER1=1
  cargo xtask consistency-run). Every run uploads the anomaly raw material
  (the EDN histories, the run summary, the checker's own output, the
  rendered report) so a later anomalous run has a clean baseline to diff
  against.

- .github/workflows/report-nightly-failure.yml: elle-register-verdict joins
  the watched workflows list, so a scheduled failure becomes exactly one
  tracked bug via the existing idempotent reporter. Its conclusion/event
  filter is untouched — a timeout overrun already surfaces as failure.

- crates/dst/tests/commit_ambiguity.rs: the DST promotion anchor — a
  committed REGRESSION_SEEDS array (the custodian.rs precedent) replayed
  through the four existing metadata-ambiguity property bodies in their
  faithful configuration, with per-seed anti-vacuity assertions so a seed
  that never activates a fault path cannot replay green silently. The
  initial set is documented honestly as a deterministic replay set, NOT yet
  bug-finding; a checker-found anomaly's minimized seed is appended per the
  promotion procedure documented in the workflow header.

- xtask/tests/consistency_ci_job.rs (new): five independent file-read
  pinning tests couple the workflow name to the routed seat constant, pin
  the schedule/dispatch-only triggers and the timeout/thinness shape, verify
  the invoked subcommand is a real dispatch arm of xtask/src/main.rs, bind
  the uploaded artifact paths to what the runner actually emits, and guard
  the reporter entry and the DST anchor — offline, container-free, and
  JVM-free, so the unprivileged merge gate stays that way.

The workflow's first live execution is deferred to a post-merge
workflow_dispatch; the run link is recorded on the issue.

Fixes #409
