core: add multipart key grammar and validated identity types

Lay the storage-key foundation for the upcoming S3 multipart-upload
support (proposal 0016): a new `wyrd_core::multipart` module defining
the validated identity types (`UploadId`, `AttemptId`, `PartNumber`,
`SlotIndex`, `Digest`) and the canonical, fixed-width key encoding for
every record the multipart protocol will use — sessions, in-flight
part slots, committed parts and their summaries, staging entries, and
retirement obligations.

Every key constructor is paired with a parser that fails closed: a
non-canonical spelling of a record (a missing zero-pad, a leading
`+`, a stray field) is rejected rather than silently accepted, so two
spellings of one record can never both parse and neither can bypass a
range scan meant to find them. That guarantee also covers a key's
retirement-mode component, which previously could report a mode from
a prefix match alone even for a truncated or non-UTF-8 key; it is now
decided only by decoding the whole key, so a caller that dispatches
on the mode can no longer be misled into treating a malformed
retirement key as a valid one.

Nothing in this module is consumed by production code yet; the store
round trips that read and write these keys land in follow-up patches.

Fixes #691
