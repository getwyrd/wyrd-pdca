core: abort multipart sessions through one shared fence batch builder

Nothing on main could abort a multipart upload: the only code that moved a
session to Aborting was the post-restore fence, which built its batch
inline. This adds abort_session in wyrd-core, the store side of
AbortMultipartUpload. It moves an Open session to Aborting at the next epoch
and installs the session's retirement obligation in the same atomic batch,
so every session an Abort fences can later be reclaimed.

The batch now has one builder, abort::fence_batch, and the restore fence
calls it in place of its inline copy, with the same preconditions and the
same puts in the same order. The two writers of the Open to Aborting edge
cannot drift apart. Restore's behaviour does not change.

Abort answers in the existing vocabulary: Fenced for an Open session,
AlreadyAborting for one already fenced (so two racing Aborts never see a
409), OperationAborted for a Completing session, and NoSuchUpload for a
Completed or missing one, writing nothing in those cases. The fence never
changes the admission count; a fenced session keeps its staged bytes and
stays counted until the terminal delete.

A commit that did not say Committed is judged from what the store holds.
On TiKV a lock held by another writer comes back as a Conflict with nothing
applied, so an unchanged session is not taken as proof that the obligation
key is taken: Abort reads the key, and calls a present key damage only if
the session is still unchanged when read again. An unexplained conflict is
retried within a bounded number of rounds. An Abort that ends while one of
its fences may still land, or before any read could say whether one landed,
returns that unknown outcome as an error that names the upload id and
classifies Indeterminate, never an error that says nothing was written.

There is no production caller of Abort yet; the S3 verb is #668. This
builds on the Create slice, commit f9514c4fcfcae1e13110cd75278e8252a1def0e0
(#894, PR #908). The new tests are crates/core/tests/multipart_abort.rs and
a seeded DST scenario in crates/dst/tests/multipart_abort.rs.
