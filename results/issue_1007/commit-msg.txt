core: fence a multipart Complete without charging rejected requests

A client that sends CompleteMultipartUpload with a wrong part list should be
able to correct the list and send it again. An earlier attempt at this
protocol, #636, did not allow that: three malformed requests used up the
session's attempts, so a fourth, correct one was refused while every part was
still stored. Abort and a full re-upload were the only way out.

Add the first phase of Complete to wyrd-core. A valid request now takes the
session to Completing and hands the caller a value that holds the fence. A
rejected one takes the session back to Open with its attempts as they were,
because a fence that wrote no segment created nothing the attempt limit bounds.
A request already invalid before the fence is answered with no commit at all.

Another publisher's fence is refused and left untouched. If this request's own
fence cannot be taken down, or a commit's outcome is unknown, the caller gets an
error that says so, never an answer.

Nothing publishes yet and no production path calls this. Publication and the S3
verb follow in later changes, so users see no change from this commit alone.
