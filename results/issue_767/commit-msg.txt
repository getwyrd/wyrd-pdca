gateway-s3: list LastModified at whole seconds, matching HEAD

A listing and a HEAD of the same object reported different modification
times whenever the stored stamp was not on a whole second, which is almost
every object. The listing kept the millisecond part (".750Z") while the
Last-Modified header, whose HTTP date format has one-second resolution,
dropped it. A sync tool that caches a listing's LastModified and then
revalidates with HEAD saw a mismatch on every object, every pass.

S3 itself lists whole seconds: 3,000 of 3,000 LastModified values sampled
from public AWS buckets in two regions, under both ListObjectsV2 and v1,
ended ".000Z", and a HEAD of a listed object agreed to the second.

Listings now truncate to the second the same way the header does, so both
name the same instant for every stored value. The store still keeps the
modification time in milliseconds (ADR-0047); only the rendering changes.
The rule is stated on both formatters and in the architecture doc's
object-metadata paragraph, and a new wire-level test checks v1 and v2
listings, HEAD and GET against each other.

Fixes #767
