d-server: advertise a routable endpoint, not the bound address

A d-server publishes an endpoint into coordination so other roles can
discover and dial it. Until now that endpoint was always derived from the
server's bound socket address. A server running in a container binds
0.0.0.0:50051, so it published http://0.0.0.0:50051 — a wildcard address
no peer can actually connect to, leaving the registration record useless
for cross-container discovery. A DNS service name could not be used as a
workaround either, because --bind only accepts a numeric socket address.

This adds a --advertise-addr ADDR flag to `wyrd d-server`. When set, the
server registers http://ADDR (a routable DNS name or NAT-mapped address)
for discovery instead of its bound address; the listen socket is
unchanged. When the flag is omitted the registered endpoint stays exactly
the bound-address value as before, so existing single-host and loopback
setups are unaffected. The small-multi-node deploy now gives each d-server
its routable service name so peers can reach the published endpoint.
