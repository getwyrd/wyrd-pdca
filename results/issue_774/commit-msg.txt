validate: add the wyrd-validate crate and its command-line surface

Proposal 0017 specifies a blackbox validator that an operator points at
their own cluster, but there was no crate to put it in. This adds
crates/validate (package wyrd-validate) as a workspace member: a library
that holds the decisions and a thin wyrd-validate binary over it. It has
no dependencies at all, so it lands with no licence decision attached;
the S3 client and its dependency audit come with #741.

The binary takes ten required flags (--endpoint, --region, --bucket,
--scenario, --duration, --workers, --seed, --out, --run-id,
--driver-placement), resolves S3 credentials, prints the resolved
configuration and exits. It issues no requests yet, and says so on
stderr.

Credentials come from AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY, else
WYRD_S3_ACCESS_KEY/WYRD_S3_SECRET_KEY, else the run is refused, matching
`wyrd s3`'s "no anonymous access". Half a pair, or a value that is not
UTF-8, is refused by name instead of falling through and signing as a
different identity. An empty variable counts as unset. The echo shows
the access-key id and never the secret.

Parsing is strict, unlike wyrd's own parser: an unknown flag, a repeated
flag, an empty value, a stray positional, or a --flag in a value slot
(`--bucket --typo`) is refused by name. A mistyped flag on a long
validation run must fail loudly, not produce a believable green over the
wrong settings.

Fixes #774
