custodian: stop one segmented object from halting reconstruction

Reconstruction read each committed object's chunk map inline, once
per queued repair, and bailed with `SegmentedMapUnsupported` the
moment it hit an object stored as a multipart ("segmented") record.
Any store that had published even one such object stopped restoring
redundancy for every other chunk it held, and the same loop rescanned
the whole namespace once per queued repair (Q scans x N objects).

Reconstruction now reads the committed namespace once per pass
through the resolver every other maintenance loop (GC, scrub,
restore) already shares, and contains a damaged or unreadable object
the same way those loops do: name it, skip it, keep going. A chunk
whose committed reference lives in a segmented record is refused,
not repaired and not silently discarded — the obligation stays
queued and the pass reports it did not fully certify the store
rather than claiming more than it read. Flat repairs land exactly as
before, with every existing classification and its gauge accounting
unchanged.

Fixes #697
