All production citations below were checked against `$PDCA_TARGET`, the supplied disposable snapshot. The patch was restored after the red leg; reverse-application checking succeeds. Findings are advisory and do not make an accept decision.

1. **FAIL — P1: damaged progress can authorize reclamation before the drain.** `decode_cleanup_walk` accepts `{"after":"ff"}` because it checks hex syntax without checking the cursor belongs to `orphan:` (`target/crates/core/src/orphan_identity.rs:235`). Cleanup resumes beyond every orphan key and writes the marker (`target/crates/custodian/src/orphan_identity.rs:255`, `target/crates/custodian/src/orphan_identity.rs:281`). My test planted an ancient mark on a live 100-chunk object and this cursor; cleanup reported `Complete` with the mark unchanged. Production unlink then installed its obligation, and a GC-only pass reclaimed fragment `701000/0` before any drain. Reject invalid cursor namespaces/bounds and restart the lap; add a regression through routing and GC. Evidence: `pdca-reviewer-1014-evidence/adversarial.log:7`, `pdca-reviewer-1014-evidence/adversarial.log:15`.

2. **FAIL — P1: an unrelated obligation leaves stale evidence eligible after routing.** Cleanup returns `Leave` solely because the mark’s event key exists, even when the indexed committed reference names the fragment and that obligation names different chunks (`target/crates/custodian/src/orphan_identity.rs:1025`). The existing F4 test deliberately constructs this state and certifies completion. I extended that sequence: preserve the ancient `g:703:1` mark on object 702, complete cleanup, drain obligation 703, unlink object 702, run GC before its drain. Fragment `702000/0` was reclaimed immediately. A present token is insufficient evidence for certifying the migration invariant; preserve the mark if required, but do not certify this unresolved live-reference case. F4’s wording needs the T5 decision rather than silently changing the contract. Evidence: `pdca-reviewer-1014-evidence/adversarial.log:17`.

3. **FAIL — P1: restored reclaiming state creates a permanent dependency cycle.** A reclaiming mark whose only namer is a flat generation obligation blocks cleanup (`target/crates/custodian/src/orphan_identity.rs:1016`). The drain waits for GC (`target/crates/custodian/src/retirement/marks.rs:477`), while GC holds reclaiming marks until cleanup completes (`target/crates/custodian/src/gc.rs:717`). The test creates the obligation through production Complete, plants the unfinished reclaim, runs production post-restore reconciliation, and alternates repair and GC six times. Every repair remains `Blocked`, every GC pass remains `Partial`, and the obligation survives; no wrapper freezes it. Distinguish this unreferenced, drain-owned case from a reclaiming mark under a live reference and provide a safe convergence path. Evidence: `pdca-reviewer-1014-evidence/adversarial.log:22`.

4. **FAIL — P1: uncertain placement is used as proof for deleting orphan evidence.** A malformed placement makes `names` accept every position of that chunk (`target/crates/custodian/src/orphan_identity.rs:454`); cleanup then drops its mark under the committed-namer branch (`target/crates/custodian/src/orphan_identity.rs:1038`, `target/crates/custodian/src/orphan_identity.rs:1066`). Conservative protection during uncertainty does not prove that a particular old server position is referenced. With a truncated RS(2,1) placement and an ancient mark on vacated server 8, cleanup deleted that mark and certified completion. After repairing the placement, unlinking, and advancing beyond grace, the server-8 fragment remained permanently unevidenced. Keep/block uncertain positions rather than deleting their only evidence. Evidence: `pdca-reviewer-1014-evidence/adversarial.log:6`, `pdca-reviewer-1014-evidence/adversarial.log:10`.

5. **FAIL — P2: the retirement-index memory bound excludes its diagnostics.** Every unreadable obligation calls `block`, which appends the entire key and diagnostic to `Index.blockers`; `read_obligations` continues to the end (`target/crates/custodian/src/orphan_identity.rs:510`, `target/crates/custodian/src/orphan_identity.rs:533`, `target/crates/custodian/src/orphan_identity.rs:859`). Consequently N malformed obligations retain N diagnostics even with an empty orphan window. The 64-record page bound does not bound retained state. This is a source-derived allocation bound, not a measured OOM. Retain bounded diagnostics, consistent with the progress record’s single blocker, while preserving the typed blocked verdict.
