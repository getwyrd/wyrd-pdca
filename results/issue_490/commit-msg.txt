core: a lapsed pending lease can no longer publish an object

A streaming PUT commits only after its last chunk arrives, so until the
commit an early chunk's fragments are protected from the custodian GC
solely by an unexpired pending-ledger lease. Two seams let an upload
whose lease had lapsed publish anyway — an object whose chunk map points
at bytes the GC is entitled to reclaim, so a later read fails or returns
missing data even though the client was told the upload succeeded (and
an overwrite replaces a healthy object with a broken one):

* Renewal: renew_pending did a blind put of every pending:<id> entry, so
  a stall past the TTL followed by a sweep was silently undone — the
  next chunk's renewal re-created the reaped entries and the upload
  proceeded. The write path also discarded the renewal's outcome.
* Commit: phase 3 (commit_create / commit_overwrite) required nothing of
  the pending ledger, so a lapse the renewal never observes — a stall
  after the last chunk, the window between the stream returning and the
  caller committing, or leases merely present-but-expired (whose bytes
  GC's expired-lease input already treats as reclaimable) — still
  published.

Renewal is now conditional and atomic: every entry is read back, and the
renewal pairs a require on the read-back value with the put in one
batch, refusing with Conflict when any entry is absent (swept) or has
lapsed. The refusal surfaces as a hard error that aborts the upload
before the next chunk is written toward commit. Phase-3 commit is
lease-conditional: both committers thread a per-chunk require on the
read-back pending entry into the same atomic batch as the inode create /
CAS, so a sweep racing the commit yields Conflict, never a publish.

Both checks use the sweep's own reap boundary — a lease is dead at
lease_expiry_millis <= now — so renewal, commit, sweep, and GC all agree
on when authority ends; renewing or committing at exactly the deadline
refuses. commit_create gains a commit-instant parameter (its callers all
have one in scope); commit_overwrite reuses its existing
orphaned_at_millis, which already is the commit instant at its one
production callsite. Reconstruction/backfill's commit_chunk_map stays
deliberately unconditional: its chunks are already committed and hold no
pending entries. Healthy uploads that renew before expiry commit and
read back byte-identical, unchanged.

The residual GC-mid-pass race (a GC pass whose reference set predates a
commit that won with then-live leases) is inherent to GC's snapshot and
is tracked separately in #557.
