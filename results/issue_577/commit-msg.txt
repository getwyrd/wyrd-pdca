Add typed transient/terminal error classes across the store seams

Callers, retry logic, and operators could not tell "try again" (the peer is
unreachable, slow, or busy) from "retry cannot help" (the data is gone, the
config is wrong): apart from four specific typed faults, everything crossing
the storage trait seam was an opaque boxed error string, and over the
chunkstore gRPC seam only the DATA_LOSS -> IntegrityFault case reconstructed
client-side — a timeout or an unreachable node arrived as an unclassifiable
transport string (proposal 0010, "Scope boundary" item 6).

wyrd-traits now exports the failure class as a value: ErrorClass, a closed
set of four (transient, terminal, integrity, indeterminate) with stable
single-word labels a metrics consumer can key series on up front (issue
575's error-by-class counter), one classify() source-chain walker
generalizing is_integrity_fault, and a TransientFault seam type that wraps
the producing backend's error rather than replacing it, so the wire status
and the concrete cause stay reachable underneath the class. IntegrityFault
stays a distinct terminal class (corruption carries a repair obligation no
other terminal fault has), CommitUnknownResult stays indeterminate — never
collapsed into the transient/terminal binary — and anything the seam does
not recognise defaults to terminal, so retry logic can only ever act on a
known-transient signal instead of retry-storming an unknown fault.

The class survives the gRPC seam on the existing status conventions, with
no proto change: the server sends a store-named transient fault as
UNAVAILABLE (the DATA_LOSS precedent), and the client reconstructs
UNAVAILABLE, CANCELLED, DEADLINE_EXCEEDED and RESOURCE_EXHAUSTED as
transient — CANCELLED included because tonic renders an expired channel
deadline as CANCELLED, not DEADLINE_EXCEEDED, so excluding it on the
textbook reading would drop the very timeout case the proposal names. A
channel that cannot be dialed is transient (unreachable); a malformed
endpoint URI stays terminal (invalid config, which no retry fixes).

Backends produce the class at the error types they already had: TiKV's
OperationTimedOut and FoundationDB's RetryBudgetExhausted each expose a
synthetic TransientFault through source(), staying downcastable at the top
of the box — wrapping them instead would have silently broken the existing
top-level downcasts, including a safety assertion that a timed-out commit
is NOT an OperationTimedOut. redb is embedded and has no transient class to
produce; that is asserted by test rather than assumed.

Also records the ratified typed-errors/M4 sequencing decision in proposal
0010's sequencing note, as its graduation criteria require.
