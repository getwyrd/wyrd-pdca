Run the d-server test container image as a non-root user

The d-server runtime container image ran its process as root (uid 0): the
runtime stage never created an unprivileged account and set no USER, so the
service started with full root privileges it does not need. That enlarges the
blast radius if the process or image is ever compromised.

The runtime stage now creates a dedicated unprivileged system account
(dserver, 10001:10001), pre-creates and hands ownership of the /data directory
to it, and switches to that user before the entrypoint so the started process
runs unprivileged while retaining write access to its data directory. A fixed
uid/gid keeps the identity stable across rebuilds. A regression test guards the
ordering so the image cannot silently regress to running the role as root.

Fixes #286
