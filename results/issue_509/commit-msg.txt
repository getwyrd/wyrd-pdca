feat(509): serve bulk DeleteObjects (POST /bucket?delete)

Stock S3 clients could not remove objects in bulk: a
`POST /bucket?delete` request answered 501 NotImplemented, so
`aws s3 rm --recursive` and `aws s3 sync --delete` fell back to one
request per object or failed outright. The gateway now serves the
operation: it deletes each requested key and returns an S3
<DeleteResult> reporting each key as <Deleted> or <Error>, honouring
the Quiet flag.

Delete is idempotent, as S3 requires — a key that was already absent
is still reported deleted. Each key in the body is the literal object
name: it is XML-entity-decoded once and used verbatim, never
percent-decoded, so a key written as a%2Fb deletes a%2Fb, not a/b.

Because this path is destructive, the whole request body is validated
as a well-formed XML document before any key is touched. Any body that
is not a well-formed <Delete> document — or that names more than 1000
keys or exceeds the buffered-size cap — is refused with 400
MalformedXML and deletes nothing.

Fixes #509
