custodian: fence open upload sessions after a metadata restore

Restoring the metadata store from an older image can bring back an
upload session that was torn down after that image was taken. Its staged
bytes may already be reclaimed, yet the session reads as Open, so a
retried Complete could publish an object over data that is gone. The
post-restore pass never looked inside session records, so nothing
stopped this.

The pass now ends with a fence. Every session the image holds Open moves
to Aborting at the next epoch, in one commit with the retire obligation
that owes its staged residue and every part. The commit holds only if
the session is still exactly what the pass read and the obligation key
is free, so a session that changed under the pass, or a key already
taken, is named for a human instead of overwritten. A session the pass
cannot fence (undecodable, epoch at u64::MAX, or Completing, whose fence
comes later) is left as is and named the same way.

The report gains sessions_fenced and sessions_unsettled, and the CLI
verdict prints both. The fence runs after the chunk checks, and if it
fails the audit summary is still emitted, marked incomplete and never
clean, before the error is returned.
