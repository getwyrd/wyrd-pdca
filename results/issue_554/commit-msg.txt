custodian: run GC in the deployed role so deletes reclaim bytes

The deployed custodian role never ran garbage collection: both of the run
loop's reconcile passes handed the collector nothing, and the only GC
context the server crate constructed belonged to the post-restore marking
pass (dc503cd6d9d0b8bb2e3d64bb88a206a6857b52bb), which marks but never
deletes. GC is the only thing that reclaims fragment bytes — a delete or
overwrite orphans its fragments into the ledger for GC to reap — so on a
real cluster every delete, overwrite, completed reconstruction, and
rebalance leaked its displaced bytes forever.

The run loop now runs a third, separately fenced GC pass after scrub and
reconstruction. It reclaims an orphaned fragment only once its recorded
reader-safe grace deadline has elapsed; the window is derived from the
longer of the two trusted pending-lease TTLs (60 s CLI, 30 s gateway) — a
conservative floor, not a proven reader-safety bound — exactly as the
shipped restore pass derives its own. The pass runs only when every
operator-configured endpoint is connected and reachable this pass, gated
on the --endpoints count rather than on runtime reachability alone (which
a degraded startup defeats); otherwise it defers and preserves all
orphan/pending evidence, so a skipped server's garbage is reaped on a
later whole-fleet pass and "skipped" is never mistaken for "collected".
The deferral pauses all reclamation while any configured server is absent
— deliberate: a paused reclaim recovers in full, a false "collected" is a
permanent leak.

Because this arms an always-on deleting pass, the duplicate
--endpoints/--ids refusal that previously guarded only the one-shot
--reconcile-after-restore path is hoisted to guard every path: a server
listed under two identities leaves a live fragment protected under one
identity and unreferenced under the other, and GC would delete it.

GC's expired-pending input still treats the bare lease TTL as its grace,
so do not run `wyrd custodian` against a shared write-taking backend
before #490's lease-conditional commit merges (residual race tracked as
#557).

Fixes #554
