**One implementation finding: reject malformed responses in the new test helper (P2).** The production gateway was not observed emitting malformed responses; the defect is in what the new test accepts. `signed_request` ignores `Content-Length`, `dechunk` returns immediately on the zero-size line without checking the terminal CRLF, and its `size + 2` slice skips two bytes without validating their contents. A response with the expected payload but broken framing therefore still satisfies the round-trip assertion. This independently confirms `gate-logs/T4-batch-review.log:10`.

The exact response-decoding statements and `dechunk` were extracted from the target and compiled with `rustc`; `reviewer-parser.log:2` records the results:

- Valid `1\r\na\r\n0\r\n\r\n`: accepted as status 200 and body `a`.
- Missing terminal CRLF, `1\r\na\r\n0\r\n`: incorrectly accepted identically.
- Invalid chunk delimiter, `1\r\naXX0\r\n\r\n`: incorrectly accepted identically.
- `Content-Length: 2` with body `a`, and `Content-Length: 0` with body `a`: both incorrectly accepted.

Enforce declared lengths and chunk delimiters/termination, preferably through an existing strict parser, and cover these counterexamples. The probe can be reproduced by running `reviewer-scratch/parser-probe`; its source is `reviewer-scratch/parser-probe.rs`. This finding is routed through T5 as an implementation repair, not an architectural decision.
