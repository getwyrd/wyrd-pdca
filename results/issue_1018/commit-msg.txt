feat(server): add `wyrd mpu abort` to end an upload the reaper skips

The multipart reaper only judges an upload stamped with the clock it
reads. An upload stamped under any other clock is named for an operator
and then left alone, and no command existed for the operator to act. An
open or completing upload in that state kept its records, its staged
bytes and its admission slot for good. Enough of them turned every new
CreateMultipartUpload into a permanent 503 SlowDown.

`wyrd mpu abort --upload-id ID [--data-dir DIR] [--metadata-backend B]`
is that operator exit. It moves exactly one open or completing upload to
aborting in a single commit, together with the obligations that reclaim
what it holds. For a completing upload that includes the segment records
of that attempt only, never an earlier or later one. It deletes nothing
itself: the clock-free teardown that `wyrd custodian
--reap-abandoned-uploads` already runs does the rest, and the abort
prints that command spelled for the store it acted on.

A completed or absent upload is refused with exit 1 and a message naming
what was found. An upload that is already aborting is left alone with
exit 0. The command takes exactly one upload id, no wildcard and no
clock-source flag.

This is an interim verb on the development CLI. Its authority is host
access to the metadata store, with no listener and no new auth path. It
moves onto the management API of proposal 0008 when that lands, with the
same semantics and records.

Fixes #1018
