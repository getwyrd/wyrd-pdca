## Verified backend facts (tikv-client 0.4.0 — so Do doesn't re-derive them)

- **Write-conflict signal:** a write-write conflict is `tikv_client::Error::KeyError(Box<kvrpcpb::KeyError>)` with the `conflict: Option<WriteConflict>` field `Some`. In a **pessimistic** txn it can surface at `get_for_update` (lock time) *or* `commit()` (prewrite) — classify at **both**. Do **not** use the raw single-key `compare_and_swap` (can't mix with the txn API — proposal 0007 mandatory rule).
- **Drop-safety (why `conflict_or_err` is correct):** `Transaction`'s `Drop` panics only when its status is `Active` (default `CheckLevel::Panic`). `commit()` transitions to `StartedCommit` **before** its RPC and to `Committed` **only on success**, so an errored commit is already drop-safe; `rollback()` accepts `StartedCommit`, so a best-effort rollback after a failed commit is valid and releases prewrite locks promptly. After a `get_for_update` error the txn is still `Active`, so `conflict_or_err`'s rollback is what makes that path drop-safe.
- **Write-skew rule (keep, do not weaken):** every read-only precondition key is already locked with `get_for_update` and the txn is `begin_pessimistic`; TiKV SI does not conflict-check read-only keys, so this is what prevents write-skew on the `rename` read-then-commit pattern (ADR-0015; proposal 0007 §"mandatory rule").

## Invariants to hold (from the design corpus)

- **Unchanged trait:** `crates/traits/src/lib.rs` `MetadataStore`/`WriteBatch`/`Precondition`/`CommitOutcome` are byte-for-byte untouched — the whole point of M4.
- **Conflict-vs-fault partition:** `Ok(CommitOutcome::Conflict)` is reserved for a precondition miss **and** a `KeyError.conflict`; **never** retry a write-conflict at this layer; **everything else** (network, region-unavailable, PD-timeout, lock-resolution, deadlock, undetermined) stays `Err(BoxError)`.
- **Value equality:** values are stored **byte-identically** (no TiKV-side normalization) so CAS is exact and a legitimate value is never spuriously rejected — already true in the skeleton; the tests must not weaken it.
- **Gate honesty:** `cargo xtask ci` remains the single gate and must pass without a live TiKV; the contention run is additive (endpoint-gated), reached in CI/manual via `cargo xtask tikv-conformance` against the `deploy/` throwaway.
