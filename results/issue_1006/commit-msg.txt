validate: grade the required rows of the capability matrix

The capability matrix could not yet judge the operations a server must
support. Commit a4cdce13c2c94cb740203c056793d0991c9ec268 added the matrix
but left those rows unproved unless they answered with a 5xx. So a run
against pre-0.1 could never pass, and a server that returned the wrong
bytes, lost a written key or failed a bulk delete was never reported as a
failure.

Each required row now reads a fixed list of facts: its status, the headers
it names, its body or document, and the follow-up HEADs after a delete. A
fully correct run passes. A wrong answer fails the run and names the row
and the kind of failure. An answer that proves too little, such as a body
cut off after correct bytes, leaves the run inconclusive. It never hides a
wrong answer that also arrived.

A lost or cut-off follow-up HEAD stays unproved even if another HEAD of the
same key answers 404. A runner that retries a timed-out HEAD and records
both attempts gets an inconclusive result.

The classifier is pure and nothing in the binary calls it yet. The smoke
run in #939 will be its first caller.

Fixes #1006
